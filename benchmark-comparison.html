Both primary policies get four cheap-model initial call opportunities per stage. The serial policy passes each preceding retained implementation and executed public/prior-stage evidence to the next builder, preserving all checkpoints. The independent policy gives every builder the same stage-start source without peer outputs. Both use the same stronger reviewer and bounded repair/escalation rules. Matching opportunities does not make actual token usage or evidence identical.
