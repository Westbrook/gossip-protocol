## Actual browser and transport boundary

The Python owner captures the exact Git commit/tree and source inventory, closed
profile and fixture bytes, immutable Python image, runtime, environment, driver,
helper, admission and limits. An independently owned `ExternalHead` protects the
single-use `OwnerJournal`. No caller can supply a physical browser result or
resume an uncertain intent. Failed output directories are retained; each physical
class owns a fresh output and candidate source store.

The candidate server uses the existing strict `RoleSpec`: source/input mounts
read-only, no network, no capabilities, UID/GID 65534, one CPU, 256 MiB memory/swap,
64 PIDs, and the owned bounded DB volume. A source-free keeper holds that volume.
The trusted initial-state bootstrap writes only declared data before candidate
startup. No candidate Python runs on the host. Actual Engine inspection and
immutable-role/StartedAt/PID comparisons bind the exact server epoch.

The separate host Node driver launches Chromium through documented Playwright
APIs, using Playwright 1.62.1 and Chromium revision 1234. Node, browser executable,
package trees and browser manifest are hashed. The actual launched browser
version is checked. It has a fresh HOME, no inherited credentials, fixed viewport
1280x980, locale en-US and UTC, fresh contexts, Chromium sandbox enabled, a closed
proxy and DNS configuration, disabled nonproxied WebRTC, blocked service workers
and WebSockets, cancelled downloads, and closed extra pages. Nonmatching frames
and unsupported traffic are retained as diagnostic unavailability.

This is **not an OS firewall or memory-capped browser sandbox**. Route handling,
proxy settings and the Chromium sandbox do not prove arbitrary native outbound
network properties or hostile browser-exploit containment. Browser close is an
acknowledged Playwright resource close plus the owned Node child exit; the reader
does not invent an independent OS census of every Chromium descendant. A forced
or unacknowledged close makes mechanics unavailable.

All browser requests to `http://127.0.0.1:8765` are intercepted. The driver passes
`postDataBuffer()` bytes as canonical base64 through a bounded ordered owned pipe;
it never parses/stringifies candidate JSON to carry a counter. The owner retains
the original message before dispatch. Each request creates a separate trusted
probe container sharing only the independently inspected current server network
namespace. The helper has no candidate source or DB mount. Helper attach/start/
wait/final inspection, raw request/response, listener inventory and exact donor
continuity are retained. The new browser-specific donor/identity/probe module is
an explicit source fork; it does not pretend to be an old closed HTTP profile.

The bridge projects actual browser headers to HTTP/1.1: it supplies explicit Host,
Connection:close and exact Content-Length while preserving admissible end-to-end
headers and original body bytes. It is a **DOM/UI family over a declared bridge**,
not native Chromium TCP/framing or published-port qualification. Complete
Content-Length, terminal chunked and EOF-delimited response forms are accepted.
The original raw headers and wire body remain retained even when the fulfillment
projection removes framing fields. Redirects, cookies, content disposition,
content encoding, informational responses, trailers, non-ASCII headers, duplicate
end-to-end headers and nominated extension hop fields are outside the faithful
`route.fulfill()` profile. They make this observation unavailable; they are not
new product restrictions or product failures. Native-network/download semantics
need a later, separately qualified browser lane.

## Evidence and decisions

The trusted driver records DOM facts obtained through accessible-role/label
locators. It permits native or equivalent ARIA semantics and flexible job row
wording. Only Intake type is required to be a native select. Expected states are
host-only wait conditions; no expected answer, pass flag, case ID or private
selector is sent to a candidate HTTP field or mounted candidate directory.
Candidate JavaScript cannot write the owner's pipe directly.

The complete current `/api/jobs` response supplies the job identity inventory for
the visible listitem census. A one-to-one token match permits flexible wording
and catches extra or duplicated rows without treating a one-job action as the
whole inventory. Expected row fields use that whole-list association instead of
the broad per-ID text locator; genuinely ambiguous associations stay unavailable. Missing rows or unavailable inventory remain unavailable. Only
source-key result buttons are graded inside Documents; auxiliary buttons are
allowed. Namespace visibility follows the observed native select value, including
a lawful JSON default that hides it.

Literal HTML evidence is limited to the declared document-opening action. The
driver holds original image element handles immediately before selection and
records newly created images with the literal fixture's exact attributes inside
Document details afterward. Unrelated or preexisting images and global marker
values provide no imported-content failure evidence. This is a bounded positive
rendering check, not complete detection of arbitrary script effects or transient
elements removed before observation. Complete literal text is checked separately.

The reader requires the actual live owner and current external checkpoint. It
reconstructs role creation, Engine requests, raw attachment frames, helper exit,
server donor, seed bootstrap and driver argv/actions/staged bytes. It joins each
fulfilled reply to the original probe body. Screenshots and traces are original
bounded binary artifacts, split into journal records with whole-file descriptors.
They are diagnostic evidence; a candidate-provided “pass” is never consulted.
Server application stdout/stderr is not captured by this family; raw Engine,
helper, wire, Node stderr, browser diagnostics, screenshots and traces are retained.

Selectors are `CASE:ACTION:dom`, `CASE:ACTION:api`, `CASE:ACTION:mutation`, plus the
history mechanics facet. Host comparisons inspect actual complete JSON types and
exact integer tokens, DOM row/button facts, and separate actual API control reads.
Complete wrong request bodies, wrong complete job/graph results, wrong displayed
integers, invalid enabled actions, or the scoped positive imported-HTML rendering
are discrepancies. Missing readiness, incomplete frames, lost process capture,
ambiguous JSON, observer allocation exhaustion and unsupported bridge semantics
are unavailable. Known discrepancies and unavailable facets are separate lists;
a later missing observation cannot erase an already captured wrong mutation.
A 15-second wait expiry adds no product-latency requirement.

The three negative qualifications require specific original witnesses after the
live-owner reader authenticates the source, server and Chromium launch. D01
requires the exact stale integer 9007199254740994 in the original browser body
and the completely sent probe bytes. D02 requires the absent heading, its exact
DOM unavailable selector, the actual mutated complete page, and complete other
DOM/API facts. D03 requires the actual GET `/` HTML response, observed EOF, and a
declared Content-Length exactly one greater than the retained body. Generic
infrastructure unavailability cannot qualify these controls. Their pure paired
comparisons carry no physical authority.

Response headers use an own-property, null-prototype object when passed to
Playwright, preserving legal `__proto__` and `constructor` header names.

Input action order is fixed. Candidate-driven browser request counts are naturally
variable and bounded; all actual browser routes and separate trusted control GETs
are counted. Each fully observed action plans two control reads (`/api/jobs` and
`/api/documents`); there are no hidden HTTP readiness requests. Intent, confirmed
helper records, sent-complete requests, unknown request outcomes and resource
creates remain separate census fields. An incomplete row does not count as an
authenticated sent request. Helper connection retries, if refused before sending
bytes, follow the original wire helper's bounded mechanical policy and are not
additional product HTTP requests.

## Bounds and qualification ownership

The closed history budget is 1200 seconds including a 300-second Engine cleanup
reserve. Browser launch is 30 seconds, action observation is 15 seconds, wire
capture is 4 MiB with a 10-second deadline and the existing 30-second trusted-helper
process bound. Combined browser/control requests are capped at 256, request bodies
at 65,536 bytes, targets at 4096 bytes, driver messages at 8 MiB, DOM facts at
256 KiB, screenshots at 16 MiB and traces at 64 MiB. Only one route request is
executed at a time. Journal per-record/aggregate/file quotas remain active; hitting
any bound is unavailable, not adaptive expansion or automatic retry.

Seven explicit physical classes are prospective: four actual reference-source
positive histories, an actual stale browser commit-token variant, an actual
missing-heading variant, and an actual page response whose declared length
exceeds the emitted bytes. The stale variant must retain its wrong emitted body;
the missing/incomplete variants must retain unavailable observations. They never
qualify a failure by asserting a prepared output. The reference is an authored
qualification candidate, not independent study evidence. These classes require
`GOSSIP_RUN_DOCKER_TESTS=1`, consume both Engine and Chromium, and are marked
exclusive in the manifest fragment. Root alone owns their later execution.

The separate fast classes cover fixed public inputs, exact/ambiguous/malformed
JSON, large counters, framing alternatives, missing versus wrong observations,
and pure Node IPC/bridge rules. They launch no browser, Engine or provider. Scoped
author checks do not replace the root's combined static gate, full selected
regressions, physical browser qualification, independent source review or explicit
future scope-family admission. M1 exact-source catalog keys require the `m1:`
prefix; later amendment units retain their own exact catalog names. No selector
mapping is silently installed into an existing frozen scope profile.
