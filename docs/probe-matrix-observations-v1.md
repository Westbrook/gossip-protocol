# Complete generated-probe observations

The ranked swarm/orchestrator comparison needs the whole result census, including
failed and unfinished tests. `cumulative_generated_probe_matrix_reader_v1`
rebuilds the original corpus and successful reservation, then reads the enrolled
originals for every required generated cell in one contextual or merged phase.
It accepts original execution capabilities and independently retained checkpoints,
not supplied verdict dictionaries.

Missing observations remain `unavailable` in the required-cell count. Known
defects remain failures even when later cleanup or other cells are missing.
Extra, duplicate, foreign-generation and wrong-phase capabilities are rejected.
Each execution checkpoint is checked again after the other cells are read, so
an earlier execution cannot change unnoticed during the combined read. The
reader is read-only and may inspect a stopped run after its deadline.

Contextual results cannot stand in for merged results, including when both have
identical source bytes. A merged read requires its own originals and the exact
endorsed construction vector. Endorsement proves neither correct selection nor
project acceptance.

This closes the missing generated-result census, not the full ranked selection
loop. The output explicitly retains the outstanding authored public suites and
grants no selection or acceptance authority. Empty generated coverage means
`not_applicable`, not a passing experiment. Qualified aggregate resource bounds,
public-suite cell originals, controller adoption, final acceptance routes and
the matching physical rehearsal still precede the planned live comparison.

The focused checks use actual Git and original journal readers together, with
synthetic financial, source-review and Engine records. No model, candidate code
or Engine executes. They supply no swarm-versus-orchestrator quality samples.
