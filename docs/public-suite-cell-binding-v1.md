# Public tests on the intended candidate

The matched swarm/orchestrator comparison must run authored tests on each
required candidate context. A result from the accepted project tree cannot
stand in for a different proposal. `cumulative_public_suite_cell_v1` supplies the
source/release join needed before those cell executions can be admitted.

The reader authenticates the original complete reservation and child clock,
then reconstructs the appropriate source and suite from original records:

- Before review: the complete preceding milestone suite on one builder's base
  overlay. The result informs review and is not an unconditional rejection.
- Contextual comparison: the complete current suite on one candidate combined
  with the original frozen peer anchor.
- Merged comparison: the current suite on the complete endorsed construction
  vector. Construction and endorsement do not prove successful selection.

The actual Git view must be separate from the accepted project repository and
must contain the exact context tree at its declared head. Generated-test cells,
another phase's cell, changed source, wrong candidate head and missing original
child-clock bindings are rejected. Original role/financial evidence is checked
again after source capture. Cold inspection permits an earlier generation whose
base remains in accepted ancestry; it grants no execution reuse or promotion.

This binding is read-only. It declares neither a physical test result nor
qualified resource costs. An empty authored suite remains explicitly unavailable.
The actual public-cell execution owner and retained observations, complete
ranked selection/controller integration, and remaining final acceptance and
physical rehearsal gates are still required for the scheduled live comparison.

The tests use inert Git and original controller journals with synthetic finance
and mesh records. They execute no candidate code, container or model, and add no
scientific quality samples.
