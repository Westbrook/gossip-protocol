## Independent extension fixtures

Extension server code is inert source text committed to an isolated Git store.
The host can parse or compile it without executing it. Actual execution belongs
only inside the registered candidate-role container. It must not import the
candidate/reference implementation or receive hidden expected states through a
mount. Qualification responses expose deliberately authored mechanics facts;
they are not an implementation of the product specification.

Pin the 70-request row ID and full definition digest directly. Do not select a
new maximum dynamically, shorten a history, split dependent epochs, or convert
semantic catalog expectations into a mechanics pass. Root/link controls verify
actual fixture visibility and state-namespace continuity; whether the real
product correctly rejects a path remains a separate acceptance assertion.

For body controls, compare received fixture observations against independently
declared literal request bytes. A complete helper transmission does not prove
server consumption. An early-close control may have sent the complete request
before the close became observable because of buffering. Record the observed
branch once, including all unavailable evidence, without retrying to obtain a
preferred result. An uncaptured print is not an independent observation.

Supplied-transcript negative tests can verify how incomplete sends are
classified, but cannot count as a physically observed incomplete send. If the
physical early-close control records a complete send, its early-close result
is retained and the physical incomplete-send coverage remains unobserved. Do
not change frozen wire v1 or require a product server to drain a rejected body
merely to make the control pass.
