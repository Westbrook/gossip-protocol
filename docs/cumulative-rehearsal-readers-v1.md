# Original-evidence rehearsal readers

Six readers now connect the cumulative controller's declarations to the original evidence they reference. Financial records must agree with role/provider replies; process completion must agree with owned launch/wait records; Git history must preserve the initial source, released requirements, scoped proposals, selected changes and final bytes. This layer reads closed evidence and does not dispatch candidate work or reconstruct a financial owner.

`financial_rehearsal_originals_v1` and `cumulative_role_originals_v1` enforce bounded original-file and database reads, exact request/result membership, original identities and matching replies. Prechecking a path does not authorize a later unbounded reread: the underlying verifier consumes the authenticated bounded facade.

`cumulative_rehearsal_process_v1` requires the declared actor roster, actual producer-owned process closure, final action census and protected source confirmation. `cumulative_rehearsal_inventory_v1` checks the complete child artifact census and distinguishes the shared ledger from child-local immutable files.

`cumulative_rehearsal_validator_v1` links prospective directives, source/evidence publications, selections, private/protected Git proposals, integration history, all four milestone results and the final source. It preserves a rejected selection followed by legitimate repair. It checks the original partition and restart chronology rather than merely accepting a fault label.

`cumulative_rehearsal_capsule_v1` binds a closed local proof to a caller-supplied capsule digest and a separately pinned ordered six-child design envelope. Per-child approval cannot silently authorize the other five children. Canonical design digests distinguish different scalar encodings. The capsule acquires a fresh checkpoint owner on the caller's thread and closes it on success or error; it refuses an active controller's ownership. Reopening takes an exclusive lock and performs filesystem synchronization, so unchanged evidence bytes do not mean literally no filesystem side effects.
