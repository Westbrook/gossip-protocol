2. Repair a clean merge with broken meaning

A second feature permits unknown estimates: a blank estimate becomes None, and the summary must distinguish known from unknown values when counting, summing, and averaging. Zero is a known estimate. The unchanged CLI still needs to work.

Scripted branches modify different files, pass their local checks, and merge without a textual conflict. Their assumptions about unknown estimates disagree, so the combined project fails. This deliberately constructed fault isolates the recovery path; it is not evidence that the model naturally produced this conflict.

  1. Run the broken combined tree against the complete contract. A central coding worker received that tree and actual failure feedback, with at most two requests to repair it. The live worker produced a passing repair in its first request; that exact patch is frozen for all subsequent protocol cases.
  2. Freeze the first passing repair. The initial local checks and combined semantic-conflict rejection are verified once as common setup. Every protocol case then has its own Git release and repair branch, task ledger, and real Docker check of the final candidate.
  3. Inject an old-contract note after the current note. The harness filters notes by exact base and contract version before the model sees them.
  4. Expire an earlier lease, reject stale-epoch and wrong-base proposal notices, inject the valid announcement three times, and require one tested promotion.
  5. Vary delivery conditions; accepted release must remain unchanged until the valid proposal reaches the release gate and passes the current full checks.

What these experiments can change

The discovery comparison produced one paired improvement from shared notes and no paired losses in three trials. That is encouraging enough to investigate, but too small to separate a stable effect from sampling variation. Because the notes largely paraphrased the full known contract, the observed benefit could be an attention or context-packaging effect rather than discovery of new information.

The repair comparison tests a different claim: useful code can move through independent Git stores without allowing delayed, obsolete, or repeated messages to decide what becomes the release. The observed gossip path survived the modeled broker isolation because other peer routes remained available. It demonstrates that connectivity mechanism within the model, not better coding or free coordination.

The live comparison gives a preliminary signal for shared context and a working semantic-repair path. Correlated duration errors also show why simply adding more workers may reproduce the same defect. These results do not yet justify a gossip-based agent architecture. The separate candidate-swarm proposal tests a more specific next hypothesis: whether inexpensive independent implementations plus discriminating tests can improve selected correctness at a competitive total cost.
